# Public native region fixtures

These STEP files contain public mathematical primitives generated by `generate-region-fixtures.cpp`, not customer CAD. They are imported by the unchanged production pair `0f4759e678ea-191da5c8b62d`. No JavaScript positive native records are fabricated. `region-fixtures.json` binds the source and generated STEP hashes.

The generator links only its test executable against the existing pinned OCCT object cache in `maliev-cnc-kernel-tolerance`. It does not rebuild or replace the production importer. From the repository root:

```powershell
docker cp Maliev.Web.Tests/TestAssets/CncNativeInterpretation/generate-region-fixtures.cpp maliev-cnc-kernel-tolerance:/tmp/generate-region-fixtures.cpp
docker exec -w /build maliev-cnc-kernel-tolerance sh -c 'em++ -O1 -std=c++11 -fwasm-exceptions @CMakeFiles/OcctImportJS.dir/includes_CXX.rsp -c /tmp/generate-region-fixtures.cpp -o /tmp/generate-region-fixtures.o && em++ -O1 -fwasm-exceptions --bind -sSTACK_SIZE=10MB -sALLOW_MEMORY_GROWTH=1 /tmp/generate-region-fixtures.o @CMakeFiles/OcctImportJS.dir/objects1.rsp @CMakeFiles/OcctImportJS.dir/objects2.rsp @CMakeFiles/OcctImportJS.dir/objects3.rsp -o /tmp/generate-region-fixtures.js && node /tmp/generate-region-fixtures.js'
```

Copy `/tmp/region-fixture-NAME.step` from that container to this directory as `NAME.step`. The native STEP header includes generation time, so a regeneration requires deliberately updating the reviewed manifest hashes. Build output stays outside the repository.

Positive fixture STEP reals use `StepData_StepWriter::FloatWriter().SetFormat("%.17E")` to preserve binary64 round trips. This formatting choice does not loosen the native precision policy. Lowercase exponent notation was rejected by the STEP parser during generator development; only valid uppercase STEP syntax is retained.
