# Member billing Catalog persistence proof

This bounded lane joins the merged Web #495 hook with Catalog's committed licensed geography and the existing CustomerService address write/read API. It covers member billing in English at 1280 pixels and Thai at 375 pixels. It does not establish member company, shipping lookup, instant quotation, public quotation/contact, Intranet, PO or external Creden acceptance.

The test reuses `MemberAuthorityFixture`: actual pinned Auth Program login, PostgreSQL identity/refresh sessions, encrypted Secure/HttpOnly Web cookie, Redis Web session and normal AccountSessionManager/cookie validation. No authentication scheme is replaced. Real Web Program Kestrel runs the actual ThaiLookupClient, same-origin antiforgery boundary, rendered billing widget, existing UpdateAddress handler and CustomerAccountClient. Neither browser lookup nor save responses are intercepted.

Catalog Program is pinned to `3f426723743570a6c20d2c014499445abb0774e1`, with its own CI dependency pins. CustomerService and Auth binaries retain the existing separate hosted preparation pins. The fixture provisions a short-lived RS256 service JWT with only customer read, address update and Catalog locations read permissions. Normal producer signature/lifetime/permission checks run; anonymous readiness requests return 401 and valid tokens without required permissions return 403. This is synthetic service authorization, not a live IAM grant or deployment proof. The separate country-list consumer is fixed to the seeded Thailand ID 66; country API joining is outside this lane.

The browser selects and explicitly applies a real Catalog tuple, saves through the normal address handler, then a separate CustomerService GET verifies persisted province/city/postcode and existing address identity. The test reloads the member page and verifies those fields again. Manual building, house/road and Address2 remain durable; the existing save writes both addresses and the distinct stored shipping projection is checked for preservation. Administrative codes and subdistrict are transient and are not asserted as newly persisted fields.

All databases belong to Testcontainers with UUID names and loopback mapped ports. The seed's existing disposable-target guard is retained. Child processes use an allowlisted environment, suppress all output, disable deployment and are terminated in finally; containers are disposed. Evidence contains only synthetic screenshots and a bounded receipt without raw HTML, cookies, JWTs, request headers or traces. Existing full raw coverage, formatting, dependency, secret, asset and architecture gates remain intact. Hosted passing status and exact-head run links must be recorded after execution; source assertions alone do not prove acceptance.
