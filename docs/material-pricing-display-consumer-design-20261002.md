## Proposed minimal operation linearization

Use **accepted mutation**, not a call merely waiting for stateGate, as the generation boundary. After acquiring the existing stateGate, check lifetime/caller, validate the part still exists and all configuration/build inputs are valid, then atomically replace the accepted operation's local display context with a new generation and empty rows before its first persistence await. Invalid requests (including a missing part discovered only after waiting) do not alter otherwise valid display. Queued requests neither mutate accepted configuration nor advance accepted generation; the current test measures that existing contract using actual state/store values.

For restore, validate the immutable candidate parts first, then acquire stateGate before accepting the restored entries/session and generation. Do not use unsynchronized live-list reads in callback code. Upload/model replacement and removal begin a generation only when their matched successful result is accepted under stateGate, not when the upstream RPC is merely started. Provider effects that occurred before that point are not rolled back by a local display fence. Empty remaining parts clear display without calling a pricing observer. Owner/session are instance/restoration context; a new owner must not reuse the prior instance's display state.

Renderer local quantity/material input can differ from accepted configuration while a call is queued. Existing repricing activity may hide numeric display during that local pending intent; alternatively any retained numeric display must be labeled against the accepted tuple, never implicitly the unsaved input. That presentation choice belongs to later Razor review, not an unsynchronized generation increment in the coordinator. No UI code changes in this stage.

## Immutable captured context and callback fence

After successful request Put and protected reread, capture one immutable internal context under the existing operation gate:

- local generation and pricing cancellation token;
- session ID, persisted UpdatedAt and exact owner identity;
- immutable part tuples: PartId, opaque upload reference, optional actual admitted FileId (null stays null), geometry SHA and actual admitted upload SHA where present;
- canonical selected material, color, quantity and build preference;
- canonical allowed material keys and captured part IDs.

Use copied scalar tuples/read-only collections, not retained live `entries` enumerations or geometry arrays. The synthetic historical resin fixture has no admitted FileId; nullable absence does not become a fabricated admission receipt. Keep this context private: it is a display-continuity binding, not publicly serialized authority or manufacturing proof.

Introduce one tiny local `displayGate` lock to coordinate accepted context replacement, frame reduction, cancellation/disposal invalidation and immutable snapshot reads. Mutation code already has stateGate; lock order is stateGate → displayGate. Callback takes displayGate ONLY, never awaits stateGate or performs a mutation/storage call. No subscriber or user callback is invoked while displayGate is held. Captured generation/context identity and token must still match before accepting each frame. Callback does not inspect a concurrently mutating live parts list; accepted state replacement under displayGate is the fence. Bind the captured persisted tuple when the context is installed; later known protected peer UpdatedAt drift invalidates it at existing final readback, but local progress cannot prove remote cross-tab freshness.

Callback rejects unknown part/key, canceled/disposed/stale context, illegal transition or malformed unit. Proposed per-key transition graph: absent → Pending → Completed or Unavailable. Exact duplicate frames may be idempotent; terminal value/status mutation, terminal → Pending and missing initial Pending are refused. Completed requires finite nonnegative unit amount; Pending/Unavailable require null, never numeric zero. Snapshot replacement creates copied read-only rows; a prior published snapshot cannot mutate. Final quote/readiness/revision/tickets/store are never written from a frame.

On accepted new generation, known protected peer drift, caller cancellation, failed/no usable quote and disposal, invalidate current context and clear rows. On successful final shared quote, retain the matching display snapshot as a view; do not increment authoritative quote revision from frames. Cancellation already delivered to a dependency cannot forcibly terminate its background callback. A late callback observes the local disposed/generation/token fence and does not mutate a newer display.

## Notification and renderer followup (not implemented)

Current implementation notifies subscribers only for accepted frames. Begin/clear/disposal invalidation does **not** notify them. A later renderer must combine operation activity/error/peer invalidation rerenders with a fresh `MaterialPriceDisplay` read, rather than retain a previous callback's numeric values blindly. Subscriber check-before-invoke is not atomic with renderer dispatch; the renderer must recheck its own generation/disposed state inside `InvokeAsync`. This slice does not claim renderer thread safety or cross-tab freshness.

Restore now accepts its validated context under stateGate. Fresh-session `InitializeAsync` creation remains outside that gate: the current bound is one renderer initialization per coordinator instance, with a new instance for a new owner. Concurrent initialize/restore is not proved or fenced here. Matched real upload/removal and genuine admitted FileId/hash browser acceptance remain unproven; root explicitly excludes widening the FileService fixture in this narrow slice.

The callback may synchronously replace the immutable snapshot, then notify a captured subscriber outside displayGate. Do not wait for stateGate or call configuration/upload/remove from notifications: producer pricing is awaiting this callback while those operations hold stateGate. A future scoped subscriber must dispatch through renderer `InvokeAsync`, recheck disposed/generation inside the dispatcher, and unsubscribe **before** preview/coordinator teardown. No async-void, global bus, SignalR, browser storage or new infrastructure.

Awaited display notifications remain within the backend's existing owned callback budget; a noncooperative renderer/subscriber cannot extend producer wait. Eventual failures must be observed. Any synchronous subscriber side effects before cancellation are not claimed rolled back. Known token/check-to-write races from the lifetime design remain; a progress channel cannot strengthen protected store atomicity or authorize submission. No partial OrderQuote may be published.
